# Watchtower-Lite 技术文档

> 版本：v1.3  
> 更新日期：2026-08-01  
> 适用对象：开发、测试、部署和后续维护人员

## 1. 项目定位

Watchtower-Lite 是一个可在单机演示的 AIOps（智能运维）原型。它接收监控告警，把告警整理成事件，调用 Python Brain 收集指标、Kubernetes 事件和日志，再输出根因与修复建议。低风险修复经过规则判断后可进入自动修复流程；当前修复执行器仍为模拟实现，不会真的操作生产集群。

项目的核心价值是演示一条完整且可观测的运维事件链路，而不是替代成熟的生产级告警平台。

## 2. 总体架构

```text
浏览器 :3000
    │ HTTP / WebSocket
    ▼
Gateway :8080 ───── gRPC ─────► Brain :50052
    │                                  │
    │ 场景注册                         ├── Mock Prometheus :9090
    ▼                                  └── Mock K8s :8081
Mock Infra :9090/:8081
```

| 组件 | 技术 | 责任 | 默认端口 |
|---|---|---|---:|
| Web Console | Vue 3、Element Plus、ECharts、Vite | 事件总览、场景触发、实时诊断、明暗主题 | 3000（开发） |
| Gateway | Go、Gin、gRPC、WebSocket | 告警接入、事件管理、Brain 调度、前端 API | 8080 |
| Brain | Python、grpcio、httpx | ReAct 诊断、DeepSeek 调用、工具编排 | 50052 |
| Mock Infra | Go、Gin | 模拟 Prometheus 与 Kubernetes 数据 | 9090、8081 |

说明：Gateway 没有监听 50051。旧文档中的 `8080/50051` 是过期设计，当前实际通信方向是 Gateway 作为 gRPC 客户端连接 Brain 的 50052 端口。

## 4. 关键处理流程

1. 告警通过 Prometheus Webhook、自定义 Webhook 或 Mock API 进入 Gateway。
2. Gateway 将不同来源的数据标准化为内部 `Alert`。
3. 告警依次经过去重、静默和优先级队列。
4. Gateway 创建 `Incident`，P0/P1 立即诊断，P2/P3 先观察。
5. Gateway 通过 gRPC 流式调用 Brain。
6. Brain 先检索相似历史故障，再进入 ReAct 循环。
7. 配置了 DeepSeek 密钥时，模型决定下一步调用哪个受支持工具；未配置或请求失败时，自动退回固定顺序：指标 → K8s 事件 → Pod 日志 → 结论。
8. 每一步通过 gRPC 回到 Gateway，再由 WebSocket 推送到前端。
9. 诊断结果进入自动修复风险规则；当前执行动作是模拟日志，不会真实修改 Kubernetes。
10. `crash_loop` 可自动重启、`high_cpu` 可自动扩缩容，其余高风险动作转人工。
11. 事件进入已解决或人工升级状态，并始终保存一条中文总结结论。

## 5. 告警网关

### 5.1 HTTP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/webhook/prometheus` | 接收 Alertmanager 格式告警 |
| POST | `/webhook/custom` | 接收项目自定义告警 |
| POST | `/api/v1/mock/trigger` | 触发模拟故障 |
| GET | `/api/v1/incidents` | 查询事件列表 |
| GET | `/api/v1/incidents/:id` | 查询事件详情 |
| GET | `/healthz` | Gateway 与 Brain 健康状态 |
| GET | `/ws` | WebSocket 实时事件通道 |

请求体最大为 1 MiB。WebSocket 只允许与请求主机名一致的 Origin，降低跨站连接风险。

### 5.2 告警预处理

- 标准化：把外部字段映射为统一的 `Alert`。
- 去重：相同指纹在五分钟内只处理一次。
- 静默：匹配维护或忽略规则的告警不进入事件流程。
- 排队：P0 优先于 P1、P2、P3。
- 聚合：代码提供按服务和类别聚合的能力；当前入口主要按单条告警创建事件，不能把它描述为完整的时间窗口聚合系统。

## 6. 事件与状态机

主要状态路径：

```text
new → diagnosing → diagnosed → fixing → fixed → observing → resolved
  └→ false_alarm       └──────────────→ escalated ─────────────→ resolved
```

状态机拒绝未定义的跳转，避免事件被任意修改成不一致状态。事件目前存放在内存中，进程重启后会丢失；SQLite 仍是后续扩展项。

## 7. Brain 与 DeepSeek

### 7.1 调用方式

Brain 使用 DeepSeek 的 OpenAI 兼容 `POST /chat/completions` 接口。默认配置：

```dotenv
LLM_PROVIDER=deepseek
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-flash
LLM_API_KEY=
```

当前模型参与“选择下一项诊断工具、判断是否已有足够证据”。模型只能选择代码中注册的工具，不能生成并直接执行 shell 命令。结构化诊断结论和自动修复许可仍受本地模板与风险规则约束。

### 7.2 降级策略

出现下列任一情况时使用规则模式：

- `LLM_ENABLED=false`；
- `LLM_API_KEY` 为空；
- DeepSeek 超时、鉴权失败、限流或返回无效 JSON；
- 模型选择了不存在的工具。

降级只影响智能工具选择，不影响告警接入、Mock 查询、事件状态机、WebSocket 和前端展示。

### 7.3 诊断工具

| 工具名 | 数据来源 | 当前实现 |
|---|---|---|
| `prometheus_query` | Mock Prometheus | HTTP 查询模拟指标 |
| `k8s_get_events` | Mock K8s | 查询模拟 Kubernetes 事件 |
| `k8s_get_logs` | Mock K8s | 查询模拟 Pod 日志 |
| `similar_incidents` | 内存故障库 | 关键词相似度匹配 |

## 8. 统一配置

### 8.1 文件与优先级

项目根目录的 `.env` 是本地实际配置，`.env.example` 是安全模板。首次克隆后先执行 `cp .env.example .env`。读取优先级为：

1. 操作系统环境变量；
2. `WATCHTOWER_CONFIG_FILE` 指向的文件；
3. 根目录 `.env`；
4. 代码默认值。

系统环境变量优先，便于 Docker、CI 和生产环境覆盖本地配置。不要把真实 API Key 写进 `.env.example`、文档、日志或前端变量；所有 `VITE_` 变量都会进入浏览器包，因此 API Key 绝不能使用 `VITE_` 前缀。

### 8.2 配置项

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WATCHTOWER_WEB_PORT` | 3000 | Vite 开发端口 |
| `WATCHTOWER_PORT` | 8080 | Gateway HTTP 端口 |
| `WATCHTOWER_BRAIN_ADDR` | 127.0.0.1:50052 | Gateway 连接 Brain 的地址 |
| `WATCHTOWER_MOCK_CONTROL_URL` | http://127.0.0.1:8081 | Gateway 注册 Mock 场景的地址 |
| `WATCHTOWER_DB_PATH` | data/watchtower.db | SQLite 事件数据库路径 |
| `BRAIN_GRPC_PORT` | 50052 | Brain gRPC 端口 |
| `MOCK_PROMETHEUS_PORT` | 9090 | Mock Prometheus 端口 |
| `MOCK_K8S_PORT` | 8081 | Mock K8s/场景控制端口 |
| `MOCK_PROMETHEUS_URL` | http://127.0.0.1:9090 | Brain 查询指标的地址 |
| `MOCK_K8S_URL` | http://127.0.0.1:8081 | Brain 查询事件和日志的地址 |
| `LLM_ENABLED` | true | 是否允许调用 LLM；无密钥仍会降级 |
| `LLM_PROVIDER` | deepseek | 提供商标识，用于日志和扩展 |
| `LLM_BASE_URL` | https://api.deepseek.com | OpenAI 兼容 API 根地址 |
| `LLM_MODEL` | deepseek-v4-flash | DeepSeek 模型名 |
| `LLM_API_KEY` | 空 | 私密 API Key |
| `LLM_TIMEOUT_SECONDS` | 30 | 单次模型请求超时 |
| `LLM_MAX_TOKENS` | 1200 | 单次响应上限 |
| `AGENT_MAX_ITERATIONS` | 10 | 每次诊断最大循环次数 |
| `AUTOFIX_OBSERVE_SECONDS` | 5 | 模拟修复完成后的观察时间（秒） |

修改端口时必须同步保证五个监听端口互不相同。一键启动的 Supervisor 会在启动前检查端口范围、配置内冲突和系统占用。

## 9. 启动与停止

### 9.1 本地开发

```bash
# 先在 .env 中填写 LLM_API_KEY；不填写也可使用规则模式
./scripts/start.sh
```

脚本会编译 Go 服务、准备 Python 环境，然后由 `scripts/supervisor.py` 持有所有真实子进程。按 Ctrl+C 后，Supervisor 按进程树关闭 Web、Gateway、Brain 和 Mock Infra，避免 Vite 的 3000 端口残留。

### 9.2 Docker Compose

```bash
docker compose -f deploy/docker-compose.yml up --build
docker compose -f deploy/docker-compose.yml down
```

Compose 同样读取根目录 `.env`，但容器间地址由服务名覆盖为 `watchtower-brain` 和 `watchtower-mock`，不能使用容器内的 `127.0.0.1` 访问其他服务。

## 10. 前端实现

前端已经完成，不再是“预留框架”。当前提供：

- 事件统计和服务拓扑概览；
- 六种故障场景触发；
- 事件列表与详情；
- 每个事件随处理阶段更新的中文总结结论；
- 端到端链路逐节点展示，每个节点可展开查看输入、处理说明和输出；
- DeepSeek 每次请求体、原始模型响应、解析结果、Token 用量与耗时展示；
- Prometheus、Kubernetes 事件和日志工具的参数与原始返回展示；
- Gateway/Brain 健康状态；
- 明暗模式切换；
- WebSocket 断线重连。
- SQLite 历史档案、处理时间轴和逐帧诊断回放；
- 告警风暴压测与去重/吞吐统计；
- 自动修复成功、验证失败及回滚演示。

### 10.1 动态 Mock 与修复闭环

Prometheus 指标、Kubernetes 事件、Pod 状态和日志现在共享同一个场景注册表。场景依次进入 `firing → fixing → recovered`；选择失败结果时进入 `failed → rolled_back`。自动修复引擎调用 Mock 动作接口后轮询场景状态，只有恢复状态通过才允许事件关闭。

### 10.2 持久化与回放

SQLite 的 `incidents` 表保存完整事件 JSON 快照，`incident_timeline` 表按顺序保存告警、状态变化、模型步骤、工具输出、自动修复、回滚和最终结论。回放 API 返回这些时间轴帧，前端只负责按节奏播放，不会再次调用模型或重复执行修复。

LLM 追踪数据不会包含 HTTP `Authorization` 请求头或 API Key。它仍可能包含告警、日志和模型返回的业务内容，因此当前页面只应运行在可信本地网络；加入用户认证与权限控制之前，不应暴露到公网。

开发模式通过 Vite 代理请求 Gateway；生产构建由 Gateway 从 `web/dist` 提供静态文件。

## 12. 已知边界与风险

| 风险或边界 | 当前状态 | 后续建议 |
|---|---|---|
| 事件无持久化 | 重启丢失 | 接入 SQLite/PostgreSQL |
| 自动修复为模拟 | 只打印动作 | 使用受限 Kubernetes API、审批、审计与回滚 |
| LLM 输出不确定 | 有 JSON 校验与规则降级 | 增加 JSON Schema、重试、限流和提示词版本管理 |
| gRPC 为明文 | 适合本地演示 | 跨主机时启用 TLS/mTLS |
| 内存去重与历史库 | 单实例有效 | 使用 Redis 和向量数据库 |
| 配置不支持热加载 | 启动时读取 | 变更后重启，或后续加入安全的热加载 |
| API 无鉴权 | 仅限可信本地网络 | 生产环境加入认证、RBAC 和审计 |

## 13. 扩展顺序建议

1. 持久化事件与诊断结果，并补齐迁移和备份。
2. 为 DeepSeek 响应增加严格 Schema、重试、并发限制、用量统计和熔断。
3. 接入只读的真实 Prometheus/Kubernetes 查询。
4. 建立审批后，再开放少量类型化修复动作；禁止把模型文本直接拼接为命令。
5. 增加认证、RBAC、租户隔离、审计日志和密钥管理服务。
