## 四、已知问题与解决方案

### 4.1 编译相关（已解决）

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 缺少 `fmt` import | `handler.go` 使用了 `fmt.Sprintf` 但 imports 未引入 | 已添加 `fmt` import |
| 缺少 `time` import | `hub.go` 使用了 `time.Now()` 但 imports 未引入 | 已添加 `time` import |
| `CanAutoFix` 多返回值误用 | Go 多返回值不能直接当 bool 用 | 改为 `canFix, _ := ...` |
| proto 未生成 | 本机无 `protoc` 命令 | 手写简化版 proto 代码（Go + Python） |
| Dockerfile 被 `go build` 误编译 | 文件名 `.go` 后缀被当作 Go 源码 | 重命名为 `Dockerfile.gateway` 等 |
| `generateScenarioData` 不可见 | 是 `PrometheusServer` 的方法，K8s 包无法调用 | 改为包级函数 |
| `main.go` 内嵌 Manager 冲突 | 与 `internal/incident/manager.go` 重复 | 重构为使用 `internal/incident` 包 |

### 4.2 运行时可能的问题（未验证）

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| Python Brain 启动失败 | 手写 proto 与 grpcio 不兼容 | 需运行时测试，必要时用 `grpc_tools.protoc` 重新生成 |
| Python 导入路径问题 | `proto/` 目录的 Python 文件导入路径 | 检查 `sys.path` 设置，可能需要调整 `PYTHONPATH` |
| Gateway 无法连接 Brain | Brain 服务启动延迟 | 增加重试机制，或让 Gateway 启动时先等待 Brain 就绪 |
| Mock 场景数据不一致 | 不同场景生成相同 service 的数据会覆盖 | 检查 `s.scenarios` map 的 key 是否按场景区分 |

### 4.3 设计上的简化点（生产环境需改进）

| 简化点 | 当前实现 | 生产环境改进 |
|--------|---------|------------|
| 告警去重 | 内存 map（5 分钟过期） | Redis + Bloom Filter |
| 告警聚合 | 单次批量聚合 | 滑动时间窗口聚合（如 5 分钟内） |
| 向量检索 | 内存关键词匹配 | FAISS / Milvus + LLM Embedding |
| 事件存储 | 内存 map | PostgreSQL + SQLite |
| 配置管理 | 硬编码 + 环境变量 | Viper 配置文件 + 热加载 |
| 自动修复 | 模拟执行（打印日志） | 真实 kubectl / K8s API 调用 |
| LLM 推理 | 规则关键词匹配 | 接入 OpenAI / 本地模型 |
| 诊断工具 | 固定顺序（指标→事件→日志） | 让 LLM 自主决策查询顺序 |
| 认证授权 | 无 | JWT + RBAC |
| 多租户 | 无 | 按 namespace/team 隔离 |
