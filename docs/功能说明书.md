# Watchtower-Lite 功能说明书

> 版本：v1.3  
> 更新日期：2026-08-01  
> 目标读者：产品、演示人员、测试人员和项目使用者

## 1. 产品是什么

Watchtower-Lite 是一个“自动接警、自动收集线索、辅助判断根因”的智能运维演示平台。

可以把它理解为一个运维值班助手：监控系统发现问题后，它先过滤重复告警，再查询指标、Kubernetes 事件和日志，把调查过程实时展示在网页上，最后给出根因、置信度和处理建议。风险较低的动作可以进入自动修复流程，但当前版本只模拟执行，不会真的修改服务器或 Kubernetes 集群。

## 2. 适合与不适合的场景

适合：

- 学习告警、事件、诊断和修复如何形成闭环；
- 演示 Go、Python、Vue、gRPC 和 WebSocket 的协作；
- 在没有真实 Kubernetes、Prometheus 的电脑上复现常见故障；
- 作为接入真实基础设施和 DeepSeek 的原型。

暂不适合：

- 直接连接生产环境并无人值守自动修复；
- 代替 PagerDuty、Datadog、Prometheus 等成熟平台；
- 存储长期事件记录或满足审计合规；
- 在公网无认证地部署。

## 3. 用户可以做什么

### 3.1 在 Web 控制台观察系统

用户打开控制台后可以看到：

- Gateway、Brain 和 Mock Infra 的服务拓扑；
- 当前事件总数、处理中、已解决和人工升级数量；
- 最近事件及其严重级别、服务、状态和时间；
- 当前事件的诊断步骤、证据、根因和修复建议；
- 每个事件从接收到结束都有一条中文“总结结论”，会随诊断、修复和验证阶段更新；
- 从告警接入到处置的完整链路，每个节点都可展开；
- LLM 节点中的每次模型输入、原始输出、解析结果、Token 用量和耗时；
- 工具节点中的查询参数与 Prometheus/Kubernetes 返回数据；
- 后端健康状态和 WebSocket 连接状态；
- 明暗模式切换按钮，主题选择保存在浏览器中。
- SQLite 历史事件档案和完整状态时间轴；
- 将已保存的诊断过程逐帧回放；
- 生成可调数量与重复比例的告警风暴，展示去重和吞吐结果；
- 选择模拟修复失败，观察验证失败、自动回滚和人工升级。

### 3.2 触发模拟故障

| 场景 | 示例问题 | 预期处理 |
|---|---|---|
| `oom_kill` | Pod 因内存不足被杀死 | 给出内存限制建议，转人工确认 |
| `high_cpu` | CPU 持续过高 | 模型诊断资源瓶颈，满足阈值后自动扩容 |
| `high_latency` | P99 延迟升高 | 给出数据库连接池或下游依赖建议 |
| `disk_full` | 磁盘空间不足 | 给出日志清理建议，转人工确认 |
| `conn_timeout` | Redis/数据库连接超时 | 给出连接数、网络或依赖建议 |
| `crash_loop` | Pod 反复崩溃 | 模型识别崩溃循环，自动重启 Pod 并观察验证 |

用户可以在页面选择场景和服务名，也可以调用 API：

```bash
curl -X POST http://localhost:8080/api/v1/mock/trigger \
  -H "Content-Type: application/json" \
  -d '{"scenario":"oom_kill","service":"payment"}'
```

### 3.3 查看实时诊断

事件处理过程中，页面会通过 WebSocket 收到状态变化和诊断步骤。典型顺序是：

1. 查询服务指标，确认告警是否真实；
2. 查询 Kubernetes 事件，查找 OOM、调度、重启等线索；
3. 查询 Pod 日志，定位错误信息；
4. 综合已有证据，输出根因和处理建议；
5. 根据置信度与风险规则决定模拟修复或人工升级。

## 4. DeepSeek 如何参与

项目已支持 DeepSeek 的 OpenAI 兼容 API。填写 `.env` 中的 `LLM_API_KEY` 后，DeepSeek 会参与选择下一步调查工具以及判断何时可以结束调查。

```dotenv
LLM_ENABLED=true
LLM_PROVIDER=deepseek
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-flash
LLM_API_KEY=在这里填写你的密钥
```

模型受到以下限制：

- 只能选择系统预先注册的只读诊断工具；
- 不能直接执行模型生成的 shell 命令；
- 自动修复是否允许，由本地风险规则决定；
- 请求失败或没有密钥时，自动切换为规则模式，项目仍能正常演示。

因此，“使用 AI”不等于“把系统控制权交给 AI”。

页面展示模型输入输出时不会包含 API Key 或 Authorization 请求头，但可能包含告警、日志等业务数据，因此不要在未增加登录和权限控制的情况下把控制台开放到公网。

## 5. 告警处理能力

### 5.1 标准化

把 Prometheus 和自定义告警转换为同一种内部格式，统一服务名、告警名、严重级别、描述、标签和时间。

### 5.2 去重

同一来源、服务、告警名称和标签形成同一指纹。五分钟内重复出现时，只保留第一次处理，避免告警风暴。

### 5.3 静默

匹配静默规则的告警会被忽略。当前规则在代码中配置，尚无页面化维护功能。

### 5.4 优先级

P0 最高、P3 最低。P0/P1 立即诊断；P2/P3 先观察，避免轻微波动引发过度处理。

## 6. 事件生命周期

告警通过过滤后会形成事件。事件可能经过以下状态：

```text
新建 → 诊断中 → 已诊断 → 修复中 → 已修复 → 观察中 → 已解决
                 └────────── 无法安全处理 ──────────→ 人工升级
```

系统使用状态机限制不合理跳转。例如，一个还未诊断的事件不能直接标记为“已修复”。事件快照与时间轴保存在 SQLite 中，Gateway 重启后仍可查询历史记录；重启前尚未完成的事件作为历史快照保留，不会自动恢复未完成任务。

## 7. 自动修复说明

| 修复类型 | 风险 | 当前处理 |
|---|---|---|
| 重启 Pod | 低 | 置信度达到阈值后模拟执行 |
| 扩缩容 | 低 | 置信度达到阈值后模拟执行 |
| 清理磁盘 | 中 | 需要更高置信度，当前仍为模拟 |
| 修改配置 | 高 | 不自动执行，只给建议 |
| 切换流量 | 高 | 不自动执行，只给建议 |

需要特别说明：执行、验证和回滚由动态 Mock 状态机完成，不代表已经接入真实 Kubernetes。Mock 会在修复后切换指标、Pod 状态、事件和日志，Gateway 会轮询健康状态；失败场景会调用模拟回滚并升级人工。

为了让演示能直观看到自动闭环，页面默认选择“Pod 反复崩溃”场景。该场景会经过模型诊断、本地安全策略批准、模拟自动重启、短时观察和“已解决”；CPU 过高场景也可在置信度满足要求时模拟自动扩容。其余高风险案例保留人工处理，这是安全策略的预期结果，并非模型没有参与。

## 8. 配置文件

项目所需变量统一放在根目录 `.env`。首次克隆后执行 `cp .env.example .env`，再填写密钥。`.env` 已被 Git 忽略，避免 API Key 被提交。

常用配置分为三组：

- 服务端口：Web 3000、Gateway 8080、Brain 50052、Mock Prometheus 9090、Mock K8s 8081；
- 服务地址：Gateway 如何连接 Brain 和 Mock，Brain 如何查询两个 Mock 服务；
- DeepSeek：是否启用、API 地址、模型、API Key、超时和最大响应长度。
- 自动修复观察：`AUTOFIX_OBSERVE_SECONDS` 控制模拟修复成功后等待多少秒再结束事件，默认 5 秒。

如果同时设置了系统环境变量和 `.env`，系统环境变量优先。这让同一套代码可以在本地、Docker 和 CI 中使用不同参数。

安全要求：

- 不要把真实 `.env` 发给别人或提交版本库；
- 不要把 API Key 写入 Vue 前端；
- 不要在截图、日志和报错信息中暴露完整密钥；
- 怀疑泄露时，应立即在 DeepSeek 控制台撤销旧密钥并创建新密钥。

## 9. 启动与关闭

### 9.1 本地一键启动

```bash
./scripts/start.sh
```

启动器会读取 `.env`，检查五个端口是否重复或被其他程序占用，然后依次启动全部服务。按 Ctrl+C 时，它会关闭整个子进程树，包括 Vite 的 Node 进程，从而避免 3000 端口残留。

### 9.2 Docker Compose

```bash
docker compose -f deploy/docker-compose.yml up --build
docker compose -f deploy/docker-compose.yml down
```

### 9.3 默认访问地址

| 服务 | 默认地址 |
|---|---|
| Web Console | http://localhost:3000 |
| Gateway API | http://localhost:8080 |
| WebSocket | ws://localhost:8080/ws |
| Brain gRPC | 127.0.0.1:50052 |
| Mock Prometheus | http://localhost:9090 |
| Mock K8s | http://localhost:8081 |

端口修改后，以 `.env` 为准。

## 10. 验收清单

- 启动前端后能看到项目概览、服务拓扑和故障场景；
- 明暗模式按钮可切换主题，刷新后选择仍保留；
- 点击任一故障场景能创建事件；
- 页面能实时显示诊断步骤和最终结论；
- 未配置 API Key 时日志显示 `rule fallback`，流程仍能完成；
- 配置有效 DeepSeek Key 时日志显示 `deepseek/deepseek-v4-flash`；
- Ctrl+C 后 3000、8080、8081、9090、50052 均被释放；
- `.env` 不出现在版本控制提交内容中。

## 12. 后续功能建议

1. 增加 SQLite/PostgreSQL，让事件和诊断可查询、可统计。
2. 增加 DeepSeek 请求用量、耗时、错误率、限流和熔断展示。
3. 把模型输出升级为严格 JSON Schema，并保存提示词版本。
4. 接入只读真实 Prometheus/Kubernetes，先观察再谈自动操作。
5. 为自动修复加入审批、RBAC、审计、验证和回滚。
6. 增加登录、多团队隔离、静默规则管理和通知渠道。
